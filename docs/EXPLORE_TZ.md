## 1. Текущее состояние (2026-10-29)

**«Исследовать»** (`explore.tsx`):
- фильтр по группам — выпадающий список, переключатель «Карточки / Таблица»;
- сетка карточек: квадратная картинка атома обрезана в узкую горизонтальную полосу (надписи на картинке срезаны), плитка «номер + символ», бейдж семейства, название, описание с многоточием, «Исследовать →», маленькая точка статуса;
- нет поиска, сортировки, фильтров по состоянию и прогрессу; прогресс по разделу не показан.

**Окно элемента** (`element-window.tsx`, `detail-window.tsx`):
- слева только картинка, под ней пустота;
- справа 10–11 вкладок, на компьютере переносятся в 3–4 строки; на телефоне — аккордеон по разделам;
- данные элемента (масса, конфигурация, свойства) — только в маркированных списках внутри вкладок;
- нет места в таблице, соседей, первооткрывателя, навигации между элементами.

**Ошибки:**
- описание бора: «Полуметаллы, применяемый в стекловолокне…» (несогласование);
- карточка AI: «Спросите: Литий», «Где применяется Литий?» (заглавная посреди фразы), если ещё не исправлено.

## 2. Проблема

## 4. Этап И1 — интерфейс на существующих данных

### REQ-EXP-01. Шапка прогресса (ученик)
1. Над панелью инструментов: «Изучено {n} из 60», «Освоено (тест ≥ 80 %): {m}».
2. Мини-кольца прогресса по семействам (цвет семейства, доля освоенных), нажатие — фильтр по семейству.
3. Статусы — **существующие статусы тем платформы** («не начата / в процессе / освоена»), без новых правил. Гость и учитель — шапка без личного прогресса.

### REQ-EXP-02. Панель инструментов
1. **Поиск** по названию (язык интерфейса), символу и номеру: «Fe», «26», «желез». Без учёта регистра и «ё/е»; результаты обновляются при вводе.
2. **Чипы семейств** (цвета атласа, как в квизе) вместо выпадающего списка; можно выбрать несколько; «Все» — сброс.
3. **Фильтр по прогрессу:** «Не начато · В процессе · Освоено» (только ученик).
4. **Сортировка:** по номеру (по умолчанию), по алфавиту. В И2 добавить: по массе, по году открытия.
5. **Вид:** «Карточки · Таблица · Список». «Список» — компактные строки: плитка, название, семейство, статус; удобен на телефоне.
6. Состояние фильтров и вида сохраняется в адресе (`?q=&family=&status=&sort=&view=`), «назад» работает.
7. Телефон: поиск во всю ширину; чипы — горизонтальная лента с затенением краёв **или** кнопка «Фильтры» с нижней шторкой — выбрать вариант, при котором нет горизонтального переполнения страницы; показать в отчёте.

### REQ-EXP-03. Новая карточка элемента
1. **Плитка элемента в стиле таблицы:** номер, символ, атомная масса (из данных урока, формат по языку: 6,94 / 6.94).
2. **Иллюстрация целиком:** вписывается в область (contain) с фоном в цвет семейства, без обрезки надписей. Пропорции области — ближе к квадрату (например, 4:3).
3. **Строка данных:** период и группа (из справочника таблицы C4). Агрегатное состояние — в И2.
4. **Описание полностью** (одно предложение); при необходимости — не больше 3 строк без обрыва на полуслове.
5. **Прогресс:** полоса «Тест: лучший результат %» и отметка «Изучено ✓» / «Освоено ★».
6. **Наведение и фокус:** свечение цветом семейства, лёгкий подъём; без анимации в «Экономии трафика» и при reduced motion.
7. **Быстрый просмотр «i»:** всплывающая карточка — 3 первых пункта «Основных фактов» + интересный факт + «Открыть урок». Компьютер — по нажатию «i» (не по наведению); телефон — нижняя шторка. Esc и крестик закрывают, фокус возвращается.
8. Кнопка **«Тест»** (сразу открывает тест элемента).
9. Кнопка **«Сравнить»** появляется в И2.

### REQ-EXP-04. Окно элемента — компоновка (компьютер и планшет ≥ 1024 px)
1. **Компактная шапка:** бейдж (символ, номер, семейство) и название в одну строку; описание — под ними, ширина ≤ 720 px; «Пройти тест» справа от названия или под описанием.
2. **Левая колонка, закреплённая (sticky) при прокрутке:**
   - переключатель **«Иллюстрация ⇄ Модель Бора»** (REQ-EXP-05);
   - блок **«Ключевые данные»** (в И1 — номер, символ, масса, конфигурация, период, группа, семейство из существующих данных; в И2 — полный набор);
   - **мини-таблица** (REQ-EXP-06);
   - навигация **«← {предыдущий} · {следующий} →»** по номеру.
3. **Правая колонка:** вкладки 5 групп (REQ-EXP-07), под ними AI-помощник и «Внешние ресурсы».
4. Клавиши ← → на клавиатуре переключают элемент, когда фокус не в поле ввода и не во вкладках.
5. Нет пустот под левой колонкой; нет горизонтального переполнения (тест `atlas-overflow.spec.ts` дополнить).

### REQ-EXP-05. Модель Бора
1. Переключатель (две кнопки-сегмента) над изображением: «Иллюстрация» / «Модель Бора». По умолчанию — «Иллюстрация».
2. Модель Бора — SVG по электронной конфигурации (логика `scripts/content-art/atoms.mjs` и квиза T2):
   - ядро с символом и номером;
   - оболочки с числом электронов и подписями «n=1: 2e⁻» (переводимыми);
   - медленное вращение электронов (выключено в «Экономии трафика» и reduced motion).
3. Для 11 элементов с ошибочной иллюстрацией (Li, C, N, O, Na, K, Ca, Sc, Mn, Ga, Xe) по умолчанию показывается **модель Бора**, пока владелец не заменит картинку. Список хранится в данных; после импорта новой картинки элемент из него убирается.

### REQ-EXP-06. Мини-таблица
1. Схема 18 × 7 + ряды лантаноидов и актиноидов, маленькие ячейки (на телефоне — точки без подписей). Текущий элемент подсвечен; соседи (сверху, снизу, слева, справа) с уроком — кликабельны.
2. Подпись: «Период {p} · Группа {g} · {блок}-блок».
3. Доступность: соседи — ссылки с названием; сама схема — `aria-hidden`, кроме ссылок.

### REQ-EXP-07. 5 групп вкладок (BR-EXP-01)
1. Группы:
   - **Обзор** — «Основные факты» и вводный текст;
   - **Строение** — атомная структура, электронные оболочки, изотопы;
   - **Свойства** — физические и химические;
   - **В природе и производстве** — нахождение в природе, получение и промышленное производство;
   - **Применение** — применение, значение в науке, энергетике и т. п., взаимодействие с другими областями.
2. Разделы урока внутри группы показываются **полностью**, подзаголовками h3, в исходном порядке. Ни один раздел не теряется.
3. Правила отнесения раздела к группе — по коду и названию раздела. Таблица соответствия для всех 60 элементов — в отчёте; разделы, которые отнесены неуверенно, — отдельным списком на утверждение.
4. Компьютер — 5 вкладок в одну строку (без переноса и прокрутки). Телефон — **аккордеон из 5 групп** (вместо аккордеона по разделам), первая открыта, в конце группы — «Следующий: {группа} →».
5. AI-помощник получает контекст активной группы (подсказки по группе).

### REQ-EXP-08. Исправления текста
- Описание бора — согласование («Полуметалл, применяемый в стекловолокне…» — точную формулировку взять из урока; RU/KK/EN).
- Карточка AI: «Спросите об элементе «{название}»», «Где применяется элемент «{название}»?» (если ещё не сделано).
- Проверить описания всех 60 элементов на такие же ошибки согласования; найденное — в отчёт.

## 5. Этап И2 — данные, сравнение, тренды (после команды)

### REQ-EXP-09. Справочник свойств элементов (BR-EXP-02)
1. Файл данных в `content/` (например, `natural-sciences/01-chemistry/elements-data.yaml`) для **всех 118 элементов**, где данные есть:
   - атомная масса;
   - электронная конфигурация;
   - блок, период, группа;
   - агрегатное состояние при 25 °C;
   - плотность;
   - температуры плавления и кипения;
   - электроотрицательность по Полингу;
   - атомный радиус;
   - год открытия и первооткрыватель(и);
   - категории опасности: огнеопасен, токсичен, радиоактивен, окислитель, едкий;
   - «Где встречается»: организм, быт, техника, природа, космос — только для 60 элементов с уроками.
2. **У каждого числового поля — источник** (PubChem, IUPAC, CRC Handbook или эквивалент). Неизвестное или неустановленное (сверхтяжёлые элементы) — `null` и в интерфейсе «нет данных». Ничего не придумывать.
3. Проверка в `content:check`: типы, единицы, диапазоны, источник обязателен.
4. **Черновик на утверждение:** `docs/ELEMENTS_DATA.md` — таблица для 60 элементов с уроками (все поля + источник); для остальных 58 — сводка, какие поля заполнены. **ОСТАНОВКА** до утверждения; после — импорт.
5. Тексты (названия первооткрывателей, «где встречается») — RU/KK/EN, KK/EN — `needs_review`.

### REQ-EXP-10. Использование данных
1. **Ключевые данные в окне** — полный набор REQ-EXP-09 с единицами; первооткрыватель — ссылка на страницу учёного, если он есть в разделе «Учёные».
2. **Значки безопасности** в окне и в быстром просмотре (иконка + подпись + пояснение в подсказке). Не пугающий тон: «Радиоактивен — работают только специалисты».
3. **«Где встречается»** — иконки-чипы в окне (Обзор).
4. Карточка: значок агрегатного состояния в строке данных.
5. «Исследовать»: фильтр **по состоянию** (газ, жидкость, твёрдое); сортировка **по массе** и **по году открытия**.

### REQ-EXP-11. Сравнение (BR-EXP-03)
1. Кнопка «Сравнить» на карточке и в окне; выбрать **2–3** элемента. Внизу экрана — лоток «Сравнение: Na · K · ✕ … [Сравнить]».
2. Экран сравнения (свой адрес `…/explore/compare?e=sodium,potassium`):
   - столбцы элементов;
   - строки — все поля справочника;
   - лучшее и худшее значение в строке выделено;
   - внизу — «Что общего / чем отличаются»: кнопка «Спросить Syntara AI» с контекстом сравнения.
3. Телефон: столбцы-карточки с горизонтальной прокруткой **внутри** блока или переключатель «по одному» — без переполнения страницы.
4. Доступность: настоящая таблица (`<table>`, заголовки строк и столбцов).

### REQ-EXP-12. Тренды в виде «Таблица» (BR-EXP-04)
1. Переключатель «Раскрасить по: Семейству · Электроотрицательности · Атомному радиусу · Температуре плавления · Плотности · Году открытия».
2. Последовательная цветовая шкала, различимая при нарушениях цветового зрения, в обеих темах. Легенда-градиент с минимумом и максимумом. «Нет данных» — серая штриховка.
3. Наведение и фокус на ячейке — значение с единицей. В `aria-label` ячейки — значение.
4. Короткая подсказка-вывод для каждого свойства (из `needs_confirmation.json`), например «Электроотрицательность растёт слева направо и снизу вверх».

## 6. Ограничения
- Тесты, квиз, «Учёные», Главная, поиск и глоссарий атласа — не менять (кроме ссылок на учёных и контекста AI).
- Статусы и XP — существующие правила, без изменений.
- Картинки атомов: файлы не менять. Подмена моделью Бора — только для 11 по списку.
- Доступность (axe без serious/critical, клавиатура, диктор), «Экономия трафика», `prefers-reduced-motion`, бюджет JS ≤ 500 КБ (сравнение и тренды — загрузка по требованию), i18n RU/KK/EN (новые тексты — `needs_confirmation.json`, KK/EN — `needs_review`).
- Нет горизонтального переполнения на 320–1920 px (дополнить `atlas-overflow.spec.ts` новыми экранами).
- CI — в фоне, не ждать в сессии; при красном — исправить в первую очередь; статус последнего CI — в отчёте.
- Коммитить только файлы задачи.
