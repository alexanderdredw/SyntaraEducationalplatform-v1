## 1. Текущее состояние (по коду, 2026-10-29)

**Квиз «Проверь знания»** (атлас, `apps/api/src/modules/atlas/atlas-quiz.service.ts`, `packages/shared/src/atlas.ts`, `apps/web/components/subjects/atlas-chemistry/quiz.tsx`):
- 10 вопросов одного типа: «маскированное описание (или факт на сложном уровне) → элемент»;
- адаптивные уровни 1–3 (окно из 5 ответов);
- неверные варианты — случайные из всех 60 элементов (`shuffle(pool…)`), на лёгком уровне всего 2 варианта;
- после ответа только «верно/неверно»;
- результат: процент, XP, список ошибок со ссылками.

**Маскировка:** `maskElementText` заменяет только точную форму названия. Формы «кислорода», «кислородом» и т. п. остаются в тексте, и ответ может просвечивать.

**Тест темы** (платформа `apps/web/components/learn/quiz.tsx`, `test-engine.ts`; атлас `topic-test.tsx`):
- движок поддерживает `single_choice`, `true_false`, `text_input` и показ объяснения;
- в химии 312 вопросов, все `single_choice`;
- **объяснений 0**;
- сложность: 109 лёгких, 200 средних, 3 сложных;
- `topic-test.tsx` атласа отрисовывает только варианты выбора.

**Общее:**
- прогресс показан текстом «k / N»;
- сложность — словом «Средний» без пояснения;
- нет клавиш выбора, нет подсказок, нет «Повторить ошибки», нет сравнения с прошлым результатом.

## 2. Проблема
Тестирование выглядит и работает слишком просто для современной образовательной платформы:
- однообразные вопросы;
- угадываемые варианты;
- нет объяснений;
- слабая обратная связь и отображение прогресса.

## 3. Решения владельца (2026-10-29)
1. Делаем этапы **T1** (оформление и обратная связь) и **T2** (новые типы вопросов химии). Этап «новые типы для всей платформы» (сопоставление, упорядочивание, классификация, редактор учителя) — **не делать**, решение позже.
2. Улучшения T1 — **во всех тестах платформы**: тест темы любого предмета — в стиле платформы (`packages/ui`); тесты атласа — в стиле атласа. Логика общая.
3. Подсказка «50/50» — **да**.
4. Режим «на время» (таймер) — **нет**.
5. Тесты атласа могут выглядеть лучше оригинала, но **в его стиле**: тёмный фон, свечение, цвета семейств, шрифты атласа.

## 4. Требования — этап T1 (все тесты)

### REQ-TST-01. Обратная связь после ответа
1. После ответа:
   - «Верно» / «Неверно»;
   - подсвечен правильный вариант (у неверного выбранного — отметка);
   - **объяснение** (если есть);
   - ссылка **«Открыть урок →»**: в атласе — окно элемента или раздел учёного; в платформе — урок темы.
2. Переход к следующему вопросу — кнопкой «Далее» или Enter (без автоперехода).
3. Анимация ответа:
   - верный — свечение (в атласе — цветом семейства элемента);
   - неверный — короткое «вздрагивание»;
   - в «Экономии трафика» и при `prefers-reduced-motion` анимации нет.

### REQ-TST-02. Прогресс и сложность
1. **Сегментированная полоса**: N делений; каждое после ответа — зелёное (верно), красное (неверно), жёлто-зелёное (верно с подсказкой). Текущее деление выделено. Рядом — «Вопрос k из N».
2. **Счётчик серии** верных ответов подряд (появляется от 2).
3. Адаптивные тесты атласа — **индикатор сложности** из трёх точек с подписью «Лёгкий / Средний / Сложный» и подсказкой «Сложность меняется по вашим ответам». При смене уровня — короткое сообщение «Отлично! Вопросы становятся сложнее» / «Сделаем чуть проще».
4. Тест темы — сложность вопроса (easy/medium/hard из `quiz.yaml`) теми же тремя точками.

### REQ-TST-03. Варианты ответа и управление
1. У вариантов — метки A/B/C/D, выбор клавишами 1–4 или A–D, Enter — подтвердить или «Далее».
2. Хорошо различимые состояния: наведение, фокус, выбран, верно, неверно, недоступен (после ответа).
3. Ввод ответа (`text_input`): поле, Enter — проверить.
4. «Верно/Неверно» (`true_false`): две крупные кнопки; клавиши 1/2.
5. Атлас: `topic-test.tsx` поддерживает **все три типа** платформы (`single_choice`, `true_false`, `text_input`) в стиле атласа.

### REQ-TST-04. Подсказка «50/50» (BR-TST-01)
1. Кнопка «50/50» у вопросов с 4 и более вариантами: убирает 2 неверных варианта. Не больше одной на вопрос и **3 на попытку**. Остаток виден: «50/50 · осталось 2».
2. Какие варианты убрать, решает **сервер**; факт использования записывается в попытку (иначе подсказку можно подделать).
3. Учёт:
   - верный ответ с подсказкой считается верным в результате (отмечен на полосе и в итогах);
   - для XP весит **0,5**:
     - тест темы: XP = round(20 × (верные_без_подсказки + 0,5 × верные_с_подсказкой) / всего), с прежним правилом «только прирост к лучшему»;
     - квиз и игра атласа: начисление = floor(сумма весов) по правилу BR-XP-05, лимит 20 XP/день.
4. У `true_false` и `text_input` подсказки нет.
5. Учитель в предпросмотре может пользоваться подсказкой; ничего не записывается.

### REQ-TST-05. Экран результата
1. Круговая диаграмма процента, «{верные} из {всего}», **«+N XP»** (фактически начислено, включая +0), отметка, сколько верных с подсказкой.
2. **Сравнение с прошлым**: «Лучший результат: X%», «+Y к прошлой попытке» (тест темы — по этой теме; квиз атласа — по этому режиму).
3. **Список ошибок**: вопрос, ваш ответ, верный ответ, объяснение (свёрнуто), ссылка на урок.
4. Кнопки:
   - **«Повторить ошибки»**: атлас — новая попытка только из ошибочных элементов; тест темы — новая попытка той же темы;
   - «Пройти ещё раз»;
   - «К уроку» / «К атласу».
5. Квиз атласа: разбивка «по семействам» (верно/всего по каждому семейству в попытке).

### REQ-TST-06. Компоновка
1. Компьютер (≥ 1024 px): карточка теста шире (до ~1100 px), в две колонки:
   - слева вопрос и варианты;
   - справа «Ход попытки» — полоса, серия, сложность, подсказки 50/50.
   Телефон: одна колонка, «Ход попытки» сверху компактной строкой.
2. Кнопка выхода «× Завершить» с подтверждением («Прогресс этой попытки не сохранится» — если так работает платформа; иначе текст по фактическому поведению).
3. Никаких наложений с плавающими кнопками платформы.

### REQ-TST-07. Умные неверные варианты (квиз атласа, BR-TST-02)
1. Всегда 4 варианта на всех уровнях.
2. Подбор по уровню:
   - **лёгкий** — неверные из **других** семейств;
   - **средний** — смесь: 1–2 из того же семейства или соседние по номеру (±2), остальные — из других;
   - **сложный** — все из того же семейства или соседние по периоду/группе.
   Если элементов не хватает — добирать ближайшими по номеру.
3. Варианты не повторяются; верный — на случайной позиции.
4. Игра про учёных: на сложном уровне — учёные близких эпох (±50 лет).

### REQ-TST-08. Маскировка без подсказки ответа (BR-TST-03)
1. В тексте вопроса скрываются название элемента **во всех формах слова** (RU и KK — падежные окончания; EN — основная форма и множественное число), символ и производные, однозначно раскрывающие ответ (например, «кислородный»).
2. Автоматическая проверка: для всех 60 элементов × 3 уровня × 3 языка текст вопроса не содержит основы названия (≥ 4 букв) и символа как отдельного слова. Если не удаётся замаскировать надёжно — элемент на этом уровне берёт другой источник текста (описание вместо факта) или пропускается.

### REQ-TST-09. Объяснения (контент)
1. Для всех **312 вопросов тестов элементов** и **13 вопросов** урока «Учёные-химики» — объяснение 1–2 предложения, по фактам урока, на RU; KK/EN — `needs_review`.
2. Подготовить файл `docs/TEST_EXPLANATIONS.md` (RU) и **остановиться для утверждения владельцем** (раздел 6). До утверждения в `content/` не вносить. Код T1 при этом продолжать: объяснение показывается, когда есть.
3. Квиз «Проверь знания» (генерируемые вопросы): объяснение собирается из данных — «Это {название} ({символ}, № {N}, {семейство}). {описание}».

## 5. Требования — этап T2 (только химия, атлас)

### REQ-TST-10. Новые типы вопросов в квизе «Проверь знания»
Генерируются сервером из **проверенных данных** (60 элементов `content/` + справочник 118 элементов таблицы C4). Новых таблиц для вопросов нет.

| Код | Вопрос | Ответ | Уровень |
|---|---|---|---|
| `symbol-to-name` | «Какой элемент обозначается символом Fe?» | 4 варианта | лёгкий |
| `name-to-symbol` | «Какой символ у натрия?» | 4 варианта символов | лёгкий |
| `fact-true-false` | Утверждение из данных: «Ксенон — благородный газ», «Атомный номер калия больше, чем у кальция» | Верно / Неверно | лёгкий, средний |
| `description` (есть) | Маскированное описание | 4 варианта | средний |
| `bohr` | Схема Бора (оболочки и электроны, **без символа**): «Какой это элемент?»; на лёгком — «Сколько электронов у этого атома?» | 4 варианта / число | средний |
| `table-click` | «Найдите на таблице: период 3, группа 16» или «Найдите кальций» | Клик по ячейке таблицы Менделеева | средний, сложный |
| `config` | «[Ne] 3s¹ — какой элемент?» | 4 варианта | сложный |
| `fun-fact` (есть) | Маскированный интересный факт | 4 варианта | сложный |
| `type-symbol` | «Впишите символ кальция» | Ввод; сравнение с учётом регистра, но «ca» → подсказка «Обратите внимание на заглавную букву» и ответ неверный | сложный |

1. В одной попытке типы **чередуются** (не больше 2 одинаковых подряд); набор типов определяется текущим уровнем.
2. Схема Бора — SVG, сгенерированная по числу электронов на оболочках (данные конфигурации), в стиле атласа; без надписей, выдающих ответ. Можно взять логику скрипта `scripts/content-art/atoms.mjs`.
3. `table-click` использует компонент таблицы C4 в стиле атласа:
   - клавиатура (стрелки и Enter), диктор;
   - на телефоне — прокрутка внутри блока;
   - «Не уверены? 50/50» для этого типа — подсветить 2 строки (период) вместо удаления вариантов;
   - только элементы, у которых есть урок (60).
4. Утверждения `fact-true-false` строятся только из полей данных (семейство, номер, период, группа, агрегатное состояние, если есть), не из свободного текста.

### REQ-TST-11. Режимы на стартовом экране квиза
- **Быстрый** — 10 вопросов, смешанные типы (по умолчанию).
- **По семейству** — выбор семейства, в котором ≥ 4 элементов с уроками; вопросы только про них.
- **Работа над ошибками** — элементы, в которых ученик ошибался в последних 5 завершённых попытках квиза; если ошибок нет — «Ошибок нет — отличная работа!» и кнопка «Быстрый».
- **Таблица-челлендж** — только `table-click`.

XP всех режимов — BR-XP-05 (1 XP за верный, вес подсказки 0,5, ≤ 20 XP в день). Учитель — предпросмотр без записи.

### REQ-TST-12. Игра «Кто этот учёный?»
Получает всё из T1 (обратная связь, полоса, 50/50, результат). Новые типы не добавляются.

- Существующие правила XP (BR-XP-01 пропорционально, только прирост; BR-XP-05) — без изменений, кроме веса подсказки 0,5.
