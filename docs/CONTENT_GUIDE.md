# Базовая программа Syntara: как готовить уроки

Базовые уроки платформы живут только в папке `content/` (SPEC 7.11, BR-CNT-01). Через сайт их не меняет никто — ни учитель, ни администратор. Изменение — это правка файлов, проверка и импорт в базу; выполняет разработчик по решению владельца.

```bash
pnpm content:check              # проверить все файлы (без базы); то же делает CI
pnpm content:import --dry-run   # показать, что изменится в базе, ничего не записывая
pnpm content:import             # записать в базу (нужны DATABASE_URL и S3_* сервера)
```

`pnpm db:seed --set=demo` тоже импортирует `content/` — на чистой базе для разработки ничего больше не нужно.

Тестовый предмет e2e (главы, глоссарий, таблица Менделеева, лента) лежит в `e2e/fixtures/content/`, не в `content/`: его загружает `pnpm db:seed --set=e2e` (CI) вместе с `content/`. Импорт с ним вручную — `pnpm content:import --extra-dir=e2e/fixtures/content`; обычный `pnpm content:import` отправляет тестовый предмет в архив.

## 1. Структура

```text
content/
├─ biology/                         # раздел каталога
│  ├─ section.yaml
│  ├─ 01-human-anatomy/             # предмет
│  │  ├─ subject.yaml
│  │  ├─ 01-cardiovascular-system/  # тема
│  │  │  ├─ ru.md                   # обязательно
│  │  │  ├─ kk.md                   # необязательно
│  │  │  ├─ en.md                   # необязательно
│  │  │  ├─ quiz.yaml               # вопросы квиза (необязательно)
│  │  │  └─ media/                  # картинки темы
│  │  └─ 02-respiratory-system/
│  └─ 02-general-biology/           # предмет без тем — в каталоге «Скоро»
└─ natural-sciences/
   ├─ section.yaml
   ├─ 01-chemistry/
   └─ 02-physics/
```

Каждый предмет лежит в разделе: предметов вне разделов у базовой программы нет.

- Имена папок — для людей. Связь с базой держат **коды** (`code`) в файлах: их нельзя менять после первого импорта, иначе получится новая тема, а старая снимется с публикации.
- Коды: латинские строчные буквы, цифры, `-` и `_`. Полный код темы в базе — `<код предмета>/<код темы>`, раздела урока — `…#<код раздела>`, вопроса — `…/q/<код вопроса>`.
- Порядок задаёт `position`: разделов — в `section.yaml`, предметов внутри раздела — в `subject.yaml`, тем внутри предмета — в `ru.md`. Номера уникальны на своём уровне; префиксы папок `01-`, `02-` — только для удобства и лучше держать их совпадающими с `position`.
- Деления на классы нет (SPEC 1.3).

## 2. Раздел и предмет

`section.yaml`:

```yaml
code: biology
position: 1
title:
  ru: Биология
  kk: Биология
  en: Biology
description:
  ru: 'Раздел: анатомия человека — и скоро больше'
  kk: 'Бөлім: адам анатомиясы — жақында тағы да көбірек'
  en: 'Section: human anatomy — and more soon'
```

`subject.yaml` — так же, `position` — порядок предмета внутри раздела:

```yaml
code: human-anatomy
position: 1
title:
  ru: Анатомия человека
  kk: Адам анатомиясы
  en: Human Anatomy
description:
  ru: Как устроены и работают системы организма человека
```

Название — до 150 символов, описание — до 1000. Русский текст обязателен.

## 3. Тема: `ru.md`

Markdown с YAML-заголовком между строками `---`.

```markdown
---
code: cardiovascular-system
position: 1
title: Сердечно-сосудистая система
description: Сердце и сосуды, обеспечивающие кровообращение.
funFact: За сутки сердце взрослого человека сокращается около 100 тысяч раз.
illustration: media/circulation.png
illustrationAlt: Схема двух кругов кровообращения. В центре — сердце, сверху — лёгкие, снизу — органы тела.
media:
  - file: media/circulation.png
    source: Собственная схема Syntara, исходник — scripts/content-art/circulation.svg
    license: own
  - file: media/heart.png
    source: Собственная схема Syntara, исходник — scripts/content-art/heart.svg
    license: own
---

Короткое вступление — текст урока, который виден до разделов.

## Основные функции {#functions}

Текст раздела: абзацы, **жирный**, списки.

- клетки получают кислород;
- уносится углекислый газ.

## Строение сердца {#heart}

![Схема сердца в разрезе: два предсердия, два желудочка, клапаны](media/heart.png)

Текст раздела.
```

| Поле | Обязательно | Ограничение | Где видно |
|---|---|---|---|
| `code` | да | код | — |
| `position` | да | целое ≥ 1, не повторяется в предмете | «Тема N», порядок |
| `title` | да | ≤ 150 | заголовок урока, карточка темы |
| `description` | нет | ≤ 1000 | первая строка «Обзора» |
| `funFact` | нет | ≤ 500 | карточка «Интересный факт» |
| `illustration` | нет | `media/<файл>` | картинка справа в «Обзоре» |
| `illustrationAlt` | если есть `illustration` | ≤ 300 | подпись для незрячих (alt) |
| `media` | для каждой картинки | `file`, `source`, `license` | — |

Правила текста:

- Разделы аккордеона — заголовки второго уровня **с кодом**: `## Название {#код}`. Заголовок первого уровня (`# …`) не нужен: название — в `title`.
- Текст до первого раздела — текст урока (необязателен). Раздел — до 200 символов в названии и до 20 000 в тексте.
- Картинка раздела — отдельной строкой `![подпись](media/файл.png)` внутри раздела, одна на раздел, подпись обязательна. В других местах картинки запрещены.
- Ссылки и HTML в тексте ученику не показываются как HTML (безопасный Markdown, REQ-NFR-SEC-06).
- В YAML текст с двоеточием и пробелом (`Аорта: главная артерия`) берите в кавычки, иначе YAML не прочитается.

## 4. Переводы: `kk.md`, `en.md`

Такой же файл, но в заголовке — только тексты и пометка проверки:

```markdown
---
title: Жүрек-қантамыр жүйесі
description: Қан айналымын қамтамасыз ететін жүрек пен қан тамырлары.
funFact: …
illustrationAlt: …
review: needs_review
---

## Негізгі қызметтері {#functions}

…
```

- `review: needs_review` — перевод подготовлен ИИ и ещё не вычитан человеком: ученик видит пометку «На проверке». После вычитки носителем языка — `review: reviewed`.
- Коды разделов совпадают с `ru.md` — так связываются переводы. Раздел, которого нет в `ru.md`, допустим (он встанет после русских разделов и покажется только на этом языке).
- Нет файла языка — ученик видит русскую версию с пометкой «Урок пока доступен на русском».
- `code`, `position`, `illustration`, `media` пишутся только в `ru.md`.

## 5. Квиз: `quiz.yaml`

```yaml
questions:
  - code: aorta
    type: single_choice        # single_choice | true_false | text_input
    difficulty: medium         # easy | medium | hard
    demo: true                 # пробный вопрос на главной (не больше одного на платформе — PH-02)
    text:
      ru: Какой сосуд несёт кровь от сердца к телу?
      kk: Қай қан тамыры қанды жүректен денеге тасымалдайды?
      en: Which vessel carries blood from the heart to the body?
    explanation:
      ru: 'Аорта — главная артерия: по ней кровь из левого желудочка идёт ко всем органам тела.'
      kk: '…'
      en: '…'
    options:                   # 2–8 вариантов, ровно один correct: true
      - text: { ru: Аорта, kk: Қолқа, en: Aorta }
        correct: true
      - text: { ru: Полая вена, kk: Қуыс вена, en: Vena cava }

  - code: veins-direction
    type: true_false           # варианты «Верно» / «Неверно» задаёт платформа
    difficulty: easy
    text:
      ru: Вены несут кровь от сердца к органам.   # в примере — только ru
    correct: false

  - code: chambers
    type: text_input           # ответ один для всех языков — подходит для чисел и формул
    difficulty: easy
    text:
      ru: Сколько камер в сердце человека? Впиши число.
    answer: '4'
```

- Тексты квиза есть на каждом языке, для которого есть файл урока, и только на них.
- Вопрос: до 1000 символов, объяснение — до 2000, вариант — до 300, ответ `text_input` — до 300 (сравнение без учёта регистра и лишних пробелов, BR-QZ-03).
- Удалённый из файла вопрос уходит в архив. Если на изменённый вопрос уже отвечали, старый уходит в архив, а новый занимает его место — история попыток не меняется.

### 5.1 Объяснения (docs/TESTS_TZ.md, REQ-TST-09)

- Объяснение (`explanation`) показывается после ответа вместе с «Верно/Неверно», правильным ответом и ссылкой «Открыть урок →». Пишите его к каждому вопросу: 1–2 предложения, **почему** ответ верный, только по фактам урока (раздел «Основные факты» и разделы урока) — без новых фактов.
- RU — эталон; KK и EN — его перевод, на проверке (пометка `review: needs_review` у `kk.md` и `en.md` урока относится и к квизу). Если в уроке есть язык, объяснение нужно и на нём.
- Порядок для большого набора: черновик в отдельном документе (как `docs/TEST_EXPLANATIONS.md` — вопрос, правильный ответ из `quiz.yaml`, объяснение) → утверждение владельцем → перенос в `quiz.yaml` → `pnpm content:check` → `pnpm content:import`.
- Объяснения всех 312 вопросов «Химии» утверждены и внесены (2026-10-29).

### 5.2 Типы вопросов

- В `quiz.yaml` — три типа платформы: `single_choice` (2–8 вариантов, в тестах атласа и платформы удобнее 4: работают клавиши 1–4 и «50/50»), `true_false`, `text_input`. Они работают в тесте темы любого предмета и в тесте элемента атласа.
- Квиз «Проверь знания» «Химии» (9 типов: символ ↔ название, «Верно/Неверно», описание, схема Бора, поиск на таблице, электронная конфигурация, интересный факт, ввод символа) в `quiz.yaml` **не пишется**: вопросы строит сервер из данных урока (`title`, `description`, `funFact` в `ru.md`/`kk.md`/`en.md`) и таблицы Менделеева. Поэтому описание и факт элемента должны быть уникальными и не повторять название (название во всех формах слова скрывается автоматически; если скрыть нельзя — элемент по этому тексту не спрашивается).
- Новые типы для всей платформы (сопоставление, упорядочивание, классификация) пока не поддерживаются — решение владельца позже.

## 6. Картинки

- Только папка `media/` темы, форматы **WEBP, PNG, JPG**, каждый файл **не больше 300 КБ**. Содержимое проверяется по сигнатуре — переименованный файл не пройдёт.
- Каждая картинка объявлена в `media` в `ru.md` с источником и лицензией:
  - `own` — собственная работа (например, SVG-схема из `scripts/content-art/`, отрисованная `node e2e/scripts/render-content-art.mjs`);
  - `CC0` или `public-domain` — с точным источником (ссылка на страницу файла и автор, если известен).
- Картинки из учебников, с сайтов и из поиска без такой лицензии — **нельзя**.
- Неиспользуемые файлы в `media/` — ошибка.
- При импорте картинка попадает в наше хранилище (одинаковые файлы не дублируются), ученик получает её по подписанной ссылке.

## 7. Что делает импорт

1. Читает и проверяет **все** файлы. Любая ошибка — импорт ничего не меняет и выводит список «файл: поле — причина».
2. В одной транзакции сопоставляет разделы, предметы, темы, разделы уроков и вопросы по кодам.
3. Неизменённое не трогает: повторный запуск без правок ничего не меняет.
4. Изменённая тема (текст, разделы, картинки или квиз) → новая опубликованная версия; автор — системный пользователь «Импорт».
5. Тема, удалённая из файлов, снимается с публикации (не удаляется: результаты учеников сохраняются). Вернулась без изменений — снова публикуется той же версией.
6. Предмет, удалённый из файлов, уходит в архив. Предмет без опубликованных тем показывается со статусом «Скоро».
7. Если что-то изменилось — запись в журнале аудита (`content.import`) со сводкой.

## 8. Главы предмета (BR-CHAP-01…05)

Темы большого предмета можно разбить на главы. В `subject.yaml`:

```yaml
chapters:
  - code: elements
    position: 1
    title: { ru: Химические элементы, kk: Химиялық элементтер, en: Chemical elements }
  - code: scientists
    position: 2
    title: { ru: Учёные-химики, kk: Химик ғалымдар, en: Chemists }
```

В `ru.md` каждой темы — `chapter: <код главы>`. Если глав нет, всё работает как раньше.

- Если у предмета есть главы, `chapter` обязателен у каждой темы, а `position` — порядок **внутри главы**. «Тема N» ученик видит сквозной: сначала все темы первой главы, затем второй.
- KK и EN названий глав без пометки считаются переводом на проверке; вычитанные можно отметить: `review: { kk: reviewed }`.
- На странице предмета темы сгруппированы по главам, у ученика — «Освоено m из n», раскрыта первая неосвоенная глава.
- Главу, удалённую из `subject.yaml`, импорт удаляет; её темы остаются, но без главы.

## 9. Глоссарий (REQ-GLOS-01…06)

Файл `glossary.yaml` в папке предмета (рядом с `subject.yaml`):

```yaml
review: { kk: needs_review, en: needs_review }
sections:
  - code: general
    position: 1
    title: { ru: Общая химия и строение атома, kk: …, en: … }
    terms:
      - code: atom
        term: { ru: Атом, kk: Атом, en: Atom }
        definition:
          ru: наименьшая частица химического элемента, являющаяся носителем его свойств.
          kk: …
          en: …
```

- Коды разделов и терминов уникальны в предмете и не меняются после импорта.
- Термин — до 150 символов, определение — до 1000; на каждом языке нужны и термин, и определение.
- Порядок терминов в файле не важен: ученик видит их по алфавиту своего языка.
- Кнопка «Глоссарий» появляется на странице предмета сама, если файл есть.

## 10. Таблица Менделеева (REQ-PTBL-01…08)

Блок включается в `subject.yaml`: `blocks: [periodic-table]`. У урока элемента в `ru.md`:

```yaml
element: { symbol: O, number: 8, group: nonmetal }
```

- `group` — семейство: `alkali_metal`, `alkaline_earth`, `transition_metal`, `post_transition`, `metalloid`, `nonmetal`, `halogen`, `noble_gas`, `lanthanide`, `actinide`.
- `content:check` сверяет символ и семейство с данными таблицы (`packages/shared/src/periodic-table.ts`); на один элемент — один урок.
- Ячейка элемента с опубликованным уроком ведёт на урок, остальные — «Скоро». Названия всех 118 элементов — в i18n (`student.periodicTable.elements`), в уроках не нужны.
- `element.color` (необязательно, `#RRGGBB` заглавными) — цвет элемента в модуле «Mendeleev Atlas»: подсветка карточки и картинки (REQ-ATL-04).

## 11. Лента времени (REQ-TL-01…05)

Файл `timeline.yaml` в папке темы — над разделами урока появляется лента:

```yaml
events:
  - year: 1869
    section: mendeleev # код раздела «## … {#mendeleev}» этой темы
    lived: { from: 1834, to: 1907 } # необязательно — годы жизни в подписи точки
    title: { ru: Периодический закон, kk: Периодтық заң, en: The periodic law }
```

- Годы — реальные; порядок в файле не важен, на ленте — по году.
- Нажатие на точку раскрывает раздел и прокручивает к нему. Блок общий: подходит истории, физике и т. д.

### 11.1 Данные окна учёного — `scientists.yaml` (docs/SCIENTISTS_TZ.md, REQ-SCI-07, 08, 09, 13)

Файл рядом с `timeline.yaml` (сейчас — `61-chemists`). Годы жизни и главное открытие берутся из `timeline.yaml` и здесь не повторяются.

```yaml
review: { kk: needs_review, en: needs_review } # без review — needs_review
scientists:
  - section: mendeleev # код раздела «## … {#mendeleev}» этой темы
    gender: male # male | female — форма подписи связи («открыл / открыла»)
    born: { ru: Тобольск, kk: Тобыл, en: Tobolsk }
    country: { ru: Российская империя, kk: Ресей империясы, en: Russian Empire }
    field: { ru: Химия, kk: Химия, en: Chemistry }
    awards: { ru: 'Медаль Дэви (1882), медаль Копли (1905)', kk: '…', en: '…' } # нет наград — поля нет
    elements: # связанные элементы — номер 1–118 и вид связи
      - { number: 31, relation: predicted }
    sources: # к ссылкам «Источников» урока — во «Внешние ресурсы»
      - { title: Britannica, url: 'https://www.britannica.com/biography/Dmitri-Mendeleev' }
    prompts: # подсказки AI-помощника: ровно 3 на вкладку и язык
      biography: { ru: [ '…', '…', '…' ], kk: [ … ], en: [ … ] }
      discovery: { ru: [ … ] }
      legacy: { ru: [ … ] }
      facts: { ru: [ … ] }
```

- Виды связи: `discovered` «открыла», `predicted` «предсказал», `named` «назвал», `structure` «определила структуру соединения с», `transmuted` «превратил азот в кислород», `electronegativity` «самая высокая электроотрицательность», `named_after` «назван в честь» (подписи — i18n `atlas.sci.rel.*`; в RU глагол согласуется с полем `gender` через `{gender, select, female {открыла} other {открыл}}`, в KK и EN форма одна; решение владельца 2026-10-31).
- Элемент с уроком — чип открывает окно элемента; без урока — чип «Скоро» ведёт к ячейке на виде «Таблица» (`?view=table&cell=<номер>`).
- `content:check`: `gender` — `male` или `female` (обязательно), раздел есть в уроке и не повторяется, номер 1–118 без повторов, `https://` в источниках, ровно 3 подсказки.
- Подразделы учёного в `ru.md` / `kk.md` / `en.md` — ровно четыре с кодами: `### … {#biography}`, `{#discovery}`, `{#legacy}`, `{#facts}` (подписи вкладок — из i18n).

## 12. Как перенести готовый сайт-предмет (по опыту «Химии»)

1. **Аудит, без изменений.** Прочитать данные и тексты сайта скриптом во временной папке; составить карту «поле сайта → место в content/», список сомнительного (факты, числа, ответы квиза, переводы, остатки чужих тем) и вопросы владельцу. Пример — `docs/CHEM_MAP.md`. Секреты сайта (ключи ИИ) не открывать и не копировать.
2. **Проверить, где на самом деле текст.** В атласе «слои» оказались только подписями, а весь текст лежал в одном поле; квизы KK и EN были другими вопросами, а не переводом. Такое видно только при чтении самих данных.
3. **Конвертер, а не ручной перенос.** Скрипт `scripts/content-import/<сайт>-<предмет>.mjs --source <папка>` (путь — только аргументом) пишет `content/`; утверждённые владельцем исправления — в `*.fixes.yaml`, новые переводы — в `*.translations.yaml`. Результат руками не правится: повторный запуск даёт тот же результат (вывод проходит через prettier).
4. **Квиз.** RU — эталон, KK и EN — его перевод (`needs_review`). Варианты ответов перемешивать детерминированно (по коду вопроса): у готовых сайтов верный ответ часто стоит на одном месте.
5. **Картинки.** Только `own`, `CC0` или `public-domain` с точным источником (страница Wikimedia Commons и автор); проверить лицензию по самому файлу, а не по подписи сайта. Картинки с ошибками или сомнительного происхождения лучше заменить собственными схемами (`scripts/content-art/`).
6. **Проверка.** `pnpm content:check`, `pnpm content:import --dry-run`, импорт дважды (второй — «изменений нет»), e2e страниц предмета, урока и новых блоков.

### 12.1 Если сайт переносится с сохранением дизайна (по опыту «Mendeleev Atlas», docs/CHEM_TZ_2.md)

1. **Эталоны до кода.** Запустить оригинал локально только для чтения (вместо файла с ключами — пустая заглушка), снять скриншоты всех экранов, окон и состояний на 1440 и 390 px в обеих темах (`docs/media/<предмет>-ref/`), составить карту интерактивных элементов, адресов и отличий (пример — `docs/ATLAS_MAP.md`) и остановиться до решений владельца.
2. **Модуль предмета.** В `subject.yaml` — `module: <код>` (допустимые значения — `SUBJECT_MODULES` в `packages/shared/src/content.ts` и CHECK `subjects_module` — новое значение только миграцией). Код модуля — `apps/web/components/subjects/<код>/`, адреса — под `/learn/subjects/:id/…`, каждая страница — отдельный маршрут (свой чанк, без `next/dynamic` при серверной отрисовке: preload такого чанка блокирует CSP).
3. **Стили оригинала.** Перенести CSS как есть, изолировав под корневым классом (`body`/`:root` → корень модуля, `body.theme-light` → `:root[data-theme='light'] .корень`, @keyframes — с префиксом). Вернуть браузерные стили, которые сбрасывает Tailwind (заголовки, списки, картинки, `revert`); не делать корень контейнером прокрутки (`overflow-x: clip`, а не `hidden`); переменные, которые оригинал использует, но не задаёт, — сбросить (`initial`), иначе подставятся токены платформы. Шрифты — локально (`next/font/local`), со стеком оригинала.
4. **Данные — только платформы.** Тексты — из `content/` (исправленные), тесты — движок квиза платформы, ИИ — учебный ИИ на сервере; сбор данных и прямые запросы оригинала к внешним API не переносятся. Тексты интерфейса — в i18n из переводов оригинала.
5. **Проверка.** Пары «эталон / платформа» по каждому экрану, axe (контраст оригинала часто ниже 4,5 : 1 — минимальные исправления и список для владельца), e2e на 1440 и 320, production-сборка без ошибок в консоли.

### 12.2 Замена картинки атома атласа после перегенерации

1. Положить новый PNG с тем же именем (`<id>_atom_lux.png`, например `oxygen_atom_lux.png`) в `assets/images/` папки атласа.
2. `node scripts/content-import/atlas-chemistry.mjs --source <папка атласа>` — конвертер пересоберёт WebP (q85, ≤ 300 КБ, иначе ошибка) в `content/natural-sciences/01-chemistry/<NN>-<код>/media/<код>-atom.webp`; остальные файлы не изменятся.
3. `pnpm content:check` → `pnpm content:import` (новая версия урока, картинка — в хранилище) → коммит изменённого WebP.
4. Если элемент был в `content/natural-sciences/01-chemistry/bohr-default.yaml` (иллюстрации с ошибкой — в окне элемента по умолчанию модель Бора, docs/EXPLORE_TZ.md, REQ-EXP-05.3): запись привязана к SHA-256 старого файла и после замены перестаёт действовать сама; удалите строку элемента из файла. Формат: `elements: [{ topic: <код урока>, image: <sha256 файла иллюстрации> }]`; `content:check` — урок-элемент с иллюстрацией существует.

## 13. Подготовка уроков с помощью ИИ

Удобный порядок для массовой подготовки:

1. Попросить ИИ написать `ru.md` по этому руководству: школьный уровень, точные факты, 4–6 разделов с кодами, описание до одной фразы, интересный факт с проверяемой цифрой.
2. Попросить 3–5 вопросов в `quiz.yaml`: правдоподобные неверные варианты, объяснение к каждому вопросу, сложность от лёгкой к сложной.
3. Попросить переводы `kk.md` и `en.md` с теми же кодами разделов и `review: needs_review`; переводы вопросов — в тот же `quiz.yaml`.
4. Схемы — только собственные: SVG в `scripts/content-art/`, PNG — скриптом отрисовки.
5. `pnpm content:check` — исправить все ошибки; `pnpm content:import --dry-run` — убедиться, что меняется только задуманное.
6. Факты проверяет человек: ИИ ошибается в цифрах и терминах. Казахские тексты вычитывает носитель языка, после чего `review: reviewed`.
