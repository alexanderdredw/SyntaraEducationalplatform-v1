# Поставщик ИИ: как подключить

> Решение владельца (2026-10-17, Q-11): реальный ИИ пока **не подключается**. По умолчанию работает `mock` (PH-19):
> публичный помощник отвечает на быстрые вопросы, учебный ИИ сохраняет вопрос и отвечает «Учебный ИИ скоро будет
> доступен», ИИ-черновик учителя — «ИИ-черновик сейчас недоступен». Адаптер реальной модели готов как заготовка.

## 1. Обязательный критерий выбора поставщика

**Хранение и обработка данных в Республике Казахстан (REQ-NFR-DATA-01, PH-16 `infra.data_residency = KZ`).**
Вопросы учеников и тексты уроков уходят поставщику, поэтому поставщик (или его размещение — облако, собственный
сервер) должен обрабатывать и хранить данные в РК. Поставщик, который этому не соответствует, не выбирается.

Остальное, что стоит сравнить: качество ответов на казахском и русском, стоимость 1000 вопросов (около 6 000 токенов
на вход и 400 на выход на вопрос), скорость первого токена, поддержка потоковой выдачи (SSE), условия хранения
запросов у поставщика (без обучения на данных учеников).

## 2. Подключение без изменения кода — только переменные окружения

Если API поставщика совместим с одним из форматов ниже, код менять не нужно: задайте переменные окружения сервера
api и перезапустите его. Ключ — только в окружении сервера, не в git (AG-10); в журналы он не попадает (ключ
вырезается из текстов ошибок, вывод ошибок SDK в консоль отключён — тест `apps/api/test/llm-adapter.spec.ts`).

| Переменная | Значение |
|---|---|
| `LLM_PROVIDER` | `mock` (по умолчанию) · `openai-compatible` · `anthropic` |
| `LLM_API_KEY` | ключ поставщика (обязателен, если не `mock`) |
| `LLM_MODEL` | идентификатор модели у поставщика (обязателен, если не `mock`) |
| `LLM_BASE_URL` | адрес API: обязателен для `openai-compatible` (обычно оканчивается на `/v1`), для `anthropic` — необязателен (свой шлюз) |

- **`openai-compatible`** — любой API в формате OpenAI Chat Completions (`POST {LLM_BASE_URL}/chat/completions`,
  `Authorization: Bearer <ключ>`, потоковый ответ `stream: true` в формате SSE `data: {...}` и `data: [DONE]`).
  Этот формат поддерживают многие облака и серверы для собственных моделей (например, vLLM, Ollama, LM Studio) —
  в том числе развёрнутые в РК.
- **`anthropic`** — API Anthropic Messages (`POST {LLM_BASE_URL}/messages`, заголовок `x-api-key`).

Проверка после смены: приложение не стартует, если для реального поставщика не хватает ключа, модели или адреса
(`apps/api/src/config/env.ts`); в журнале api при старте — строка `LLM provider: <имя>, model: <модель>` (без ключа).
Затем — вопрос на вкладке «Syntara AI» урока и на `/learn/assistant`.

Ограничения заготовки (менять — в `apps/api/src/modules/ai/ai-sdk-provider.ts`): ответ до 1 024 токенов
(`MAX_OUTPUT_TOKENS`), 1 повтор при сетевой ошибке, без дополнительных заголовков запроса, без настроек
«размышления» модели и без кеширования промпта.

## 3. Свой формат API — новый адаптер

Если API поставщика не совместим ни с одним форматом выше, нужен новый адаптер. Он реализует интерфейс
`LLMProvider` (`apps/api/src/modules/ai/llm-provider.ts`):

```ts
interface LLMProvider {
  /** Имя для журналов; 'mock' означает «поставщика нет» (BR-AI-06). */
  readonly name: string;
  /**
   * Ответ модели потоком: каждая часть текста — отдельным значением.
   * prompt.system — системная инструкция (с текстом темы), prompt.messages — последние 20 сообщений
   * {role: 'user' | 'assistant', content}, prompt.locale — язык ответа.
   * signal — отмена (ученик нажал «Остановить» или закрыл страницу): прекратить запрос к поставщику.
   * onUsage — расход токенов, если поставщик его сообщает (сохраняется в ai_messages.tokens_in / tokens_out).
   * Ошибка поставщика — исключение; текст исключения попадает в журнал, поэтому ключ из него нужно вырезать
   * (redactSecret в ai-sdk-provider.ts).
   */
  stream(prompt: Prompt, signal: AbortSignal, onUsage?: (usage: Usage) => void): AsyncIterable<string>;
}
```

Требования к адаптеру:
- только генерация текста — никаких инструментов и действий с данными (BR-AI-03);
- в запрос — только `prompt` (в нём уже нет персональных данных, BR-AI-02); ничего не добавлять из профиля;
- санитизацию ответа (HTML, ссылки) делать не нужно — её выполняет сервис после адаптера (BR-AI-07, REQ-NFR-SEC-06).

Где подключить (три места):
1. Значение в `LLM_PROVIDER` — `apps/api/src/config/env.ts` (перечисление и проверки обязательных переменных)
   и таблица 2.3 в `docs/SPEC.md`.
2. Ветка `case` в `createRealProvider()` — `apps/api/src/modules/ai/ai-sdk-provider.ts` (создание адаптера по
   переменным окружения).
3. Тест по образцу `apps/api/test/llm-adapter.spec.ts`: локальный HTTP-сервер в формате поставщика — поток, расход
   токенов, отмена, ошибка без ключа в тексте.

Остальной код (публичный помощник, учебный ИИ, ИИ-черновик) работает через `LLMProvider` и не меняется.
