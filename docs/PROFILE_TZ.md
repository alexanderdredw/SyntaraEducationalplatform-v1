## 0. Цель

У каждого вошедшего пользователя есть своё «пространство»:

| Что | Где | Назначение |
|---|---|---|
| **Личный кабинет** (Personal Dashboard) | `/account` | Центральная страница пользователя: карточка профиля, сводка по его работе, быстрые действия |
| **Профиль** (User Profile) | карточка на `/account` + в меню аватара | Аватар, имя, информация о пользователе |
| **Редактировать профиль** (Edit Profile) | `/account/profile` | Изменение личных данных: аватар, имя, сведения |
| **Настройки аккаунта** (Account Settings) | `/account/settings` | Email, пароль, вход и устройства, предпочтения |
| **Данные и конфиденциальность** | `/account/privacy` (уже есть) | Копия и удаление данных — без изменения логики |

Все четыре страницы объединены вкладками: «Обзор», «Профиль», «Настройки», «Данные». Страницы открываются внутри рабочей среды (хедер + панель навигации, NAV_TZ).

## 1. Текущее состояние
- В `users`: `display_name` (одно поле имени), `email` (у ученика необязателен), `login` (у ученика), `password_hash`, `email_verified_at`, `must_change_password`. Аватара нет: в хедере — буква на цветном круге.
- Есть: `API-ME-01…05`, смена временного пароля (`API-AUTH-05` при `mustChangePassword`), подтверждение email (`API-AUTH-06`), страница `/account/privacy`.
- Нет: редактирования имени, смены пароля по желанию, добавления/смены email, аватара, страницы профиля.

## 2. Модель данных (миграция `0009_profiles.sql` + откат)

Новая таблица — без изменения существующих столбцов `users`:

```
user_profiles
  user_id uuid PK FK users
  first_name text NOT NULL (1..40)
  last_name  text NULL     (0..40)
  about      text NULL     (≤ 300; только учитель — BR-PRF-04)
  position   text NULL     (≤ 80; только учитель: «Учитель биологии»)
  avatar_kind text NOT NULL DEFAULT 'initials' CHECK (avatar_kind IN ('initials','preset','photo'))
  avatar_preset text NULL  (код из набора, BR-PRF-02)
  avatar_media_id uuid NULL FK media_files (kind = 'avatar')
  avatar_color text NOT NULL (токен цвета для инициалов, выбирается случайно при создании)
  updated_at timestamptz
```

- **Заполнение существующих пользователей:** `first_name` / `last_name` из `display_name` (до первого пробела / остаток), `avatar_kind = 'initials'`. Никаких данных не терять.
- `users.display_name` **остаётся** и синхронно обновляется (`first_name + ' ' + last_name`), чтобы все текущие места (Battle, классы, аналитика, письма) работали без изменений.
- Новый `media_kind = 'avatar'` (если перечисление не позволяет — расширить миграцией).
- RLS: профиль читает и меняет только владелец; учитель читает имя и аватар учеников своих классов и участников своих Battle; ученик — имя, аватар и `position` учителя своего класса.
- Журнал аудита: изменение имени, email, пароля, аватара.

## 3. Личный кабинет `/account` (вкладка «Обзор»)

**Карточка профиля** (вверху, общая для ролей): аватар (≈ 96 px), имя и фамилия, роль (бейдж «Ученик» / «Учитель»), логин (у ученика) или email, школа, «На платформе с {месяц год}». Кнопка «Редактировать профиль».

**Ученик — ниже карточки:**
1. Уровень, XP, серия (как в «Достижениях», компактно) + «Все достижения →».
2. «Мой прогресс» за 30 дней (освоено X из Y тем, %) + «Подробнее →» (`/learn/progress`).
3. «С чего начать сейчас?» — тот же следующий шаг, что в показателях (BR-ST-06).
4. Класс: «Вы в классе «…»», учитель (аватар, имя), или «Подключиться к классу».
5. Ближайшие задания (до 3) + «Все задания →».
6. Последние полученные бейджи (до 3).
7. Последний Battle: место и правильные ответы, «Мои Battle →».

**Учитель — ниже карточки:**
1. Сводка: классов, учеников, предметов, опубликованных тем.
2. «Требуют внимания»: сдачи на проверку (если есть очередь проверки), ученики из блока «Требуют внимания» аналитики классов (до 5).
3. Ближайшие сроки заданий (до 5).
4. Последние Battle (до 3) с числом участников.
5. Быстрые действия: «Новый предмет», «Выдать задание», «Запустить Battle», «Создать класс».

Данные — одной операцией `API-ME-12 GET /api/me/dashboard` (ответ зависит от активной роли; только чтение, переиспользует существующие сервисы).

## 4. Редактировать профиль `/account/profile`

**Поля:**
| Поле | Ученик | Учитель | Правила |
|---|---|---|---|
| Аватар | набор, инициалы **или своя картинка** | набор, инициалы **или своя картинка** | BR-PRF-02/03/06 |
| Имя | да | да | 1–40 символов, буквы (кириллица, латиница, казахские), пробел, дефис, апостроф |
| Фамилия | да (необязательно) | да | 0–40, те же правила |
| Должность | — | да (необязательно) | ≤ 80, например «Учитель биологии» |
| О себе | — | да (необязательно) | ≤ 300 символов, без ссылок |
| Логин | только просмотр | — | BR-PRF-05 |
| Школа | просмотр (из класса или регистрации) | просмотр | изменение — `TODO(OWNER)` |

**BR-PRF-01. Имя.** Меняется сразу; новое имя видно везде (хедер, класс, аналитика, будущие Battle). В уже завершённых Battle сохраняется имя на момент игры. Изменение имени — не чаще 3 раз за 30 дней (защита от злоупотреблений); при превышении — понятная ошибка с датой, когда можно снова.

**BR-PRF-02. Аватар из набора.** 24 собственных SVG-аватара (животные, предметы, абстрактные персонажи — без людей и брендов), в `packages/ui`, в фирменных цветах, корректно в обеих темах. Плюс вариант «Инициалы» с выбором цвета из 8 токенов.

**BR-PRF-03. Своя картинка (ученик и учитель — решение владельца 2026-10-25).** Любой пользователь может загрузить свою картинку-аватар:
- JPG/PNG/WEBP ≤ 2 МБ; проверка как у обложек (тип, сигнатура, ClamAV);
- обрезка в квадрат на клиенте (простой кроп без библиотек тяжелее 30 КБ);
- **на сервере картинка перекодируется** в WEBP 256×256 и 64×64, **все метаданные удаляются** (EXIF, в том числе геолокация и модель телефона); хранится только перекодированная версия;
- хранение в нашем хранилище, выдача по подписанной ссылке;
- пока картинка проверяется — показываются инициалы; если отклонена — сообщение «Картинка не прошла проверку» и инициалы.
Под полем загрузки для ученика — подсказка: «Можно любую картинку. Лучше не загружать своё фото и фото с личной информацией — аватар видят одноклассники и участники Battle».

**BR-PRF-06. Модерация аватаров.**
- Учитель может **сбросить** аватар ученика своего класса на инициалы («Ростер» → у ученика меню «Сбросить аватар»), с подтверждением; ученик видит уведомление в профиле «Учитель сбросил аватар».
- Сотрудник поддержки может сбросить аватар любого пользователя из обращения.
- Ведущий Battle может сбросить аватар участника своей игры на время этой игры (участник показывается с инициалами).
- После сброса пользователь может загрузить новую картинку, но не чаще 5 загрузок за 24 часа (лимит на все загрузки аватара).
- Все сбросы — в журнал аудита.

**BR-PRF-04.** Поля «Должность» и «О себе» показываются ученикам класса в карточке учителя (раздел «Мой класс») и только там.

**BR-PRF-05.** Логин ученика не меняется (он может быть известен учителю и одноклассникам) — ⚠ вопрос 3.

Сохранение — кнопкой «Сохранить» с индикатором «Сохранено»; уход со страницы с несохранёнными изменениями — предупреждение. Операции: `API-ME-06 GET /api/me/profile`, `API-ME-07 PATCH /api/me/profile`, `API-ME-08 POST /api/me/avatar/upload-url` (ученик и учитель), `API-ME-13 POST /api/teacher/classes/:id/students/:studentId/avatar/reset`, `API-ME-14 POST /api/teacher/battle-sessions/:sid/participants/:pid/avatar/hide` (номера сверить со SPEC), `API-ME-09 PUT /api/me/avatar` `{ kind, preset?, mediaId?, color? }`.

## 5. Настройки аккаунта `/account/settings`

**5.1 Email**
- Показ текущего email и статуса («Подтверждён» / «Не подтверждён — отправить письмо ещё раз»).
- **Добавить email** (ученик без email) или **Изменить email**: ввод нового email + текущий пароль → письмо со ссылкой подтверждения на **новый** адрес (срок 24 ч). Пока не подтверждён, действует старый email. На старый адрес приходит уведомление «Ваш email изменён» со ссылкой «Это не я» (ведёт в поддержку).
- Новый email должен быть свободен; иначе — общее сообщение «Этот адрес нельзя использовать», без раскрытия, что аккаунт существует.
- Удалить email можно только ученику с логином (тогда восстановление пароля — через учителя), с подтверждением; учителю — нельзя (email — его логин).
- Операции: `API-ME-10 POST /api/me/email` `{ email, currentPassword }`, подтверждение — существующий механизм `API-AUTH-06` (расширить на смену адреса).

**5.2 Пароль**
- «Изменить пароль»: текущий пароль, новый (≥ 8, не равен текущему), повтор. Индикатор надёжности (простой, без тяжёлых библиотек).
- После смены — все **другие** сессии завершаются; текущая остаётся. Письмо-уведомление на email, если он есть.
- Используется существующий `API-AUTH-05` (с обязательным `currentPassword` вне режима временного пароля).
- Лимит: 5 попыток за 15 минут.

**5.3 Вход и устройства**
- «Последний вход: {дата, время}».
- Кнопка «Выйти на всех других устройствах» — `API-ME-11 POST /api/me/sessions/revoke-others`.

**5.4 Предпочтения**
- Язык интерфейса, тема, «Экономия трафика» — те же настройки, что в хедере (API-ME-02), в виде формы. Изменения синхронны с хедером.
- Уведомления — ⚠ вопрос 6 (пока раздел не показывать).

## 6. Где пользователь находит профиль

1. **Хедер:** аватар + имя → выпадающее меню: «Мой кабинет» (`/account`), «Редактировать профиль», «Настройки», «Данные и конфиденциальность», разделитель, «Выйти». С клавиатуры, Esc закрывает.
2. **Панель навигации:** внизу, над «Помощь», — компактная строка профиля (аватар + имя), ведёт на `/account`; в свёрнутой панели — только аватар.
3. **Телефон:** в меню-панели (UX-10) первым блоком — строка профиля.
4. Аватар (вместо буквы) показывается: хедер, панель, карточка класса (учитель), «Ростер» и «Карта освоения» (ученики), лобби и рейтинг Battle, пьедестал.

Компонент `Avatar` в `packages/ui`: размеры 24/32/40/64/96, варианты инициалы/набор/фото, запасной вариант — инициалы при ошибке загрузки фото, `alt` = имя.

## 7. Безопасность и приватность
- Все изменения — с CSRF; смена email и пароля требует текущий пароль; лимиты попыток.
- Профиль другого пользователя целиком не открывается никому (отдельных публичных страниц профиля нет).
- Ученики не видят email и логины друг друга.
- Фото учителя — только из нашего хранилища, по подписанной ссылке.
- Журнал аудита — раздел 2.
- Удаление аккаунта — как сейчас, через «Запросить удаление» (обращение в поддержку).

## 8. Критерии приёмки
| ID | Проверка |
|---|---|
| AC-PRF-01 | Миграция переносит имена всех существующих пользователей; ничего не теряется; откат работает |
| AC-PRF-02 | `/account` показывает карточку профиля и сводку, соответствующую роли; данные совпадают с разделами «Показатели», «Достижения», «Мои задания», аналитикой |
| AC-PRF-03 | Смена имени видна в хедере, классе, аналитике сразу; в прошедших Battle — старое имя; лимит 3/30 дней |
| AC-PRF-04 | Ученик и учитель загружают свою картинку; на сервере она перекодирована, метаданные (EXIF/GPS) удалены — проверка тестом; до проверки — инициалы |
| AC-PRF-05 | Учитель сбрасывает аватар ученика своего класса, поддержка — любого, ведущий Battle — участника своей игры; лимит 5 загрузок за 24 ч; чужой учитель сбросить не может (404) |
| AC-PRF-06 | Добавление и смена email: письмо на новый адрес, до подтверждения действует старый, уведомление на старый |
| AC-PRF-07 | Смена пароля требует текущий; после смены другие сессии завершены, текущая — нет |
| AC-PRF-08 | «Выйти на всех других устройствах» работает |
| AC-PRF-09 | Меню аватара, строка профиля в панели и в мобильном меню ведут на нужные страницы |
| AC-PRF-10 | Чужой профиль недоступен; ученик не видит email/логины других; учитель видит имя и аватар только своих учеников и участников своих Battle |
| AC-PRF-11 | Клавиатура, экранный диктор, axe, 320/390 px, обе темы; тексты RU/KK/EN через i18n (`needs_confirmation.json`) |
| AC-PRF-12 | Все существующие тесты зелёные (регистрация, вход, Battle, классы, аналитика) |
