## 1. Что за проект

**Syntara Education Platform** — адаптивная веб-платформа для школ Казахстана на языках KK, RU, EN.
- Ученики: каталог базовых предметов, уроки, квизы, учебный ИИ «Syntara AI», XP и показатели, достижения, «Мой класс», задания, Battle.
- Учителя: свои предметы, темы, материалы, публикация, вопросы квиза, выдача классу, задания, аналитика класса, Battle.
- Гости: 10 публичных страниц, каталог и «Обзор» базовых уроков, пробный вопрос, публичный помощник, заявка школы, поддержка.
- Служебная поддержка: очереди обращений и заявок школ.

**Базовая программа:** полный набор школьных предметов (алгебра, биология, физика, химия и т. д.) с наполненными уроками и картинками. Предметы общие для всех, **не делятся по классам (годам обучения)**. Учителя добавляют свои личные уроки.

**Репозиторий:** `github.com/alexanderdredw/SyntaraEducationalplatform-v1`, ветка `main`. Локальная папка владельца: `C:\Users\ALexandr\Desktop\syntara`. Код пишет **Claude Code** по ТЗ.

## 2. Роли и порядок работы

| Кто | Что делает |
|---|---|
| Владелец (Виктория) | Формулирует пожелания, принимает решения, передаёт промпты в Claude Code, присылает отчёты и скриншоты |
| Чат-консультант (этот проект) | Превращает пожелания в профессиональные ТЗ и промпты для Claude Code, проверяет отчёты и скриншоты, объясняет простым русским языком |
| Claude Code | Пишет код по SPEC/PLAN/ТЗ, тестирует, коммитит, обновляет SPEC и PLAN, пишет отчёт |

**Правила для консультанта:**
1. Писать по-русски, просто, без лишнего жаргона; термины объяснять.
2. Каждое изменение — отдельный пункт из 5 частей: **текущее состояние → проблема → что изменить → ожидаемый результат → критерии приёмки**.
3. Сохранять существующий функционал. **Не добавлять ничего, что владелец не согласовал.** Если что-то неясно — спросить владельца или записать вопрос `TODO(OWNER)`, а не придумывать.
4. **Крупная или рискованная задача** (новая функция, БД, API, безопасность, много экранов) → отдельный файл ТЗ в `docs/` проекта + короткий промпт со ссылкой на него. **Мелкая задача** → только промпт.
5. Промпты давать **целиком, готовыми к вставке** в Claude Code.
6. Не принимать решения за владельца в спорных местах. Ошибки прошлого: ограничение регистрации ученика кодом класса, привязка Battle к классу, разрешение аватарки ученика — всё это консультант задал «по умолчанию» без согласования, и потом пришлось исправлять. Лучше спросить.
7. Проверяя отчёт Claude Code, объяснять владельцу: что сделано, что не сделано, что проверить самой, какие вопросы задал Claude Code и какой ответ рекомендован.

**Как Claude Code получает контекст:** он не видит чат. Каждая сессия начинается с `CLAUDE.md` → `docs/SPEC.md` → `docs/PLAN.md` («Текущее состояние»). Продолжить работу в новой сессии: «Прочитай CLAUDE.md, docs/SPEC.md и docs/PLAN.md (раздел «Текущее состояние»). …». Если промпт ссылается на прошлый отчёт или вопросы, лучше отправлять его в ту же сессию Claude Code; в новой сессии — добавить строку контекста (что за задача, какие коммиты, где отчёт).

**Длительность задач** (решение владельца 2026-10-27, раздел «Режимы работы» в CLAUDE.md):
- **Быстрый режим** (по умолчанию для мелких задач — тексты, вёрстка 1–3 экранов, небольшие баги; без изменений БД, API, прав и безопасности): lint, typecheck, unit-тесты и e2e только затронутого; 1–2 скриншота изменённых экранов (телефон + компьютер); после commit + push CI не ждать — сообщить номер коммита. Статус CI проверяется в начале следующей задачи; если красный — сначала исправление. Отчёт короткий.
- **Полный режим** (крупные задачи по ТЗ, БД/API/права/безопасность/загрузка файлов, команда «полная проверка», конец итерации): весь DoD (lint, typecheck, ~570 unit/integration, ~500 e2e, сборка), скриншоты и ожидание зелёного CI (~20–25 мин).
- Если режим неясен — Claude Code выбирает полный и объясняет почему.
- Lighthouse CI в GitHub Actions — только для push в main и ручного запуска (не для pull request).

## 3. Архитектура и стек

- Монорепозиторий pnpm + Turborepo, TypeScript strict, Node ≥ 22.
  - `apps/web` — Next.js 15 (App Router), React 19, Tailwind 4, Radix UI, next-intl (RU/KK/EN; тексты в `packages/shared/i18n/*.json`).
  - `apps/api` — NestJS 11.
  - `apps/worker` — BullMQ (проверка файлов, таймеры Battle, очистка и т. п.).
  - `packages/db` — Drizzle ORM, PostgreSQL 16 (через PgBouncer), миграции.
  - `packages/shared` — Zod-схемы, i18n, общие функции (сборка ESM).
  - `packages/ui` — дизайн-токены и компоненты.
- Инфраструктура (Docker Compose): PostgreSQL, Redis, MinIO (S3), ClamAV + olevba (проверка файлов), Mailpit (письма в разработке), nginx.
- Тесты: Vitest, Playwright (e2e + axe). CI — GitHub Actions: lint, typecheck, тесты, «Repository files», `pnpm deps:check` (knip), бюджет JS ≤ 500 КБ, Lighthouse CI.
- Локальный запуск: Docker Desktop → `pnpm dev` → `pnpm db:migrate` → `pnpm db:seed --set=demo` → http://localhost:3000. Письма — http://localhost:8025.
- Права доступа проверяются только на сервере; секреты — только в переменных окружения сервера (`.env` никогда не попадает в git и логи).
- ИИ: по умолчанию mock-провайдер. Реальный подключается переменными `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL` (`docs/AI_PROVIDER.md`). Требование: данные хранятся в Казахстане.
- Realtime Battle: SSE + REST + Redis Pub/Sub + таймеры BullMQ.

## 5. Ключевые функции (как устроено сейчас)

**Навигация (одна панель для всего, гостевые страницы доступны после входа).** Панель ученика:
- Главная;
- УЧЁБА: Каталог, Мой класс, Мои задания (счётчик невыполненных; красный при просрочке), Syntara AI, Battle;
- МОЙ ПРОГРЕСС: Показатели, Достижения (точка «новое»);
- ПЛАТФОРМА: О проекте, Школам;
- внизу: Помощь, Свернуть панель.

Выход из аккаунта нужен редко — он в меню профиля, а не в панели. Активен всегда ровно один пункт. На телефоне — мобильное меню (UX-10).

**Каталог и «Мой класс».** Каталог — только базовые предметы платформы. Предметы учителя показываются только в «Мой класс» (`/learn/class`), вместе с карточкой класса и ближайшими заданиями.

**Базовые уроки.** Только файлы `content/` + импорт (`docs/CONTENT_GUIDE.md` → `pnpm content:check` → `pnpm content:import`). На сайте их **никто не может править**; учителя правят только свои уроки.

**Регистрация и вход.**
- Ученик регистрируется сам по эталону `docs/media/student-auth.png`: код класса и email необязательны, школа — из справочника или вручную.
- Учитель: Имя, Фамилия, Email, Пароль, Школа (необязательно); обращение на «вы».
- Обе формы на общей карточке `auth-card.tsx`.
- **Ученик входит только через вход ученика, учитель — только через вход учителя.**

**Классы и коды.**
- Код класса: алфавит без похожих символов (`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`), хранится в виде хэша.
- Код Battle: `^[A-Z]{3}[1-9]{3}$` (например, KTR583), уникален среди активных игр.
- Коды полностью независимы; существующие классы и коды сохранены.

**Battle (в стиле Kahoot).**
- Учитель создаёт викторину и запускает игру; ученики входят по коду. **Членство в классе не требуется.**
- Вопросы с таймером, пьедестал из трёх, история результатов. Интерфейсы учителя и ученика раздельные.
- **XP за Battle не начисляется.**

**Удаление.**
- Учитель может удалить черновик темы, который ни разу не публиковался и не имеет заданий.
- Может удалить картинку галереи, если она не используется как обложка.
- Опубликованное не удаляется — только снимается с публикации.

**Профиль.**
- `/account`: вкладки Обзор / Профиль / Настройки / Данные.
- Шапка с обложкой, календарь активности, заполненность профиля, список устройств.
- Письмо о входе с нового устройства — **только учителям**.
- Аватар: **ученик не загружает свою картинку** — только готовые варианты или инициалы. Фото может загрузить только учитель.

**Файлы.**
- Материалы урока: PDF, DOCX, PPTX, ODT, TXT. Каждый файл проверяется ClamAV и olevba.
- **Таблицы (xlsx, xls, xlsm, xlsb, csv, ods) запрещены** из соображений безопасности: макросы, инъекция формул.

**Показатели.**
- Учебный год 2026–27, четверти: I 01.09–25.10; II 02.11–27.12; III 11.01–21.03; IV 29.03–25.05.
- Даты начала и конца года ещё нужно сверить с приказом Минпросвещения РК.

## 6. Решения владельца, которые нельзя нарушать

1. Сначала функционал, дизайн — в конце. Порядок: … → 10 → **8.5 (UI/UX, React Bits)** → **11 (качество и выпуск)**.
2. React Bits подключается только в 8.5. Выбор компонентов — через страницу-витрину `/ru/dev/ui`, где кандидаты показаны рядом. Подключаются только выбранные владельцем.
3. Базовые уроки не редактируются через сайт; предметы не делятся по классам обучения.
4. Регистрация ученика самостоятельная, без обязательного кода класса.
5. Battle не зависит от класса; коды класса и Battle независимы; XP за Battle нет.
6. Ученик не загружает свою аватарку (пока).
7. Вход строго по роли формы.
8. Таблицы к загрузке запрещены.
9. Предметы учителя — только в «Мой класс», не в каталоге.
10. Секреты (`.env`) никогда не попадают в git и логи.
11. При оптимизации и очистке:
    - не переписывать историю git;
    - не удалять тома Docker с данными;
    - не трогать эталонные изображения и `content/`;
    - удалять только то, что одобрила владелец.
12. ИИ пока mock; реальный провайдер — позже, с хранением данных в РК.
13. Скриншоты в отчётах — WebP, ширина ≤ 1600 px, коммитить только итоговые.
14. Готовые сайты-предметы переносятся «контент + блоки»: содержание — в `content/` через конвертер и файлы правок (не руками), особые функции — общими блоками платформы (главы, глоссарий, таблица Менделеева, лента времени); код чужого сайта не встраивается (CHEM_TZ, 2026-10-27).
15. Квиз на KK и EN — перевод утверждённого RU с пометкой «На проверке»; картинки — только собственные (`own`) или public domain / CC0 с точным источником; выдуманные изображения реальных людей не используются.
16. Главы — только у базовых предметов; нужны ли они учителю — открытый вопрос.
