# Syntara Education Platform

## Источник требований
- Полная спецификация: `docs/SPEC.md` — единственный источник требований. При расхождении с чем-либо прав `docs/SPEC.md`.
- Скриншоты-эталоны и схемы: `docs/media/` (T04–T10 — кабинет учителя, U01–U13 — ученик, er*.png — схемы БД, arch.png — архитектура).
- Скриншоты публичной части S01–S26 — в `docs/media/public/`, если папка есть.

## Обязательные правила
- Перед любой задачей прочитай раздел 0 спецификации (правила агента AG-01…AG-10, Definition of Done 0.5).
- Работай строго по плану раздела 12, по одной итерации за раз. Не начинай следующую итерацию без явной команды.
- Реализуй только описанное. Ничего не придумывай: неясное бери из раздела 11 (заглушки); если и там нет — `TODO(OWNER): <вопрос>` и выключи функцию флагом.
- Видимые тексты — дословно из спецификации, только через файлы i18n (`packages/shared/i18n/*.json`).
- Права доступа проверяются только на сервере (раздел 7.1). Секреты — только в переменных окружения сервера.
- Схема БД меняется только миграциями (раздел 5). Не удаляй ограничения целостности.
- Указывай ID требований (REQ-*, BR-*, AC-*) в названиях тестов и в сообщениях коммитов.

## Скриншоты отчётов (docs/OPTIMIZATION_TZ.md, 6.5)
- Новые скриншоты — только WebP (quality ≈ 85), ширина ≤ 1600 px.
- Коммитить только итоговые снимки; промежуточные «до/после» рабочих прогонов не коммитить.
- Эталоны (`docs/media/image*`, `student-auth*`, `ux/*-ref.png`, `public/`) и файлы, на которые ссылаются документы, не менять. После правок документов — `node scripts/opt/check-doc-paths.mjs`.

## Стек (раздел 2)
TypeScript strict · pnpm + Turborepo · Next.js 15 + React 19 + Tailwind 4 + Radix UI · NestJS 11 + Drizzle ORM · PostgreSQL 16 · Redis/BullMQ · S3 (MinIO) · Vitest + Playwright.

## Команды (после итерации 1)
- `pnpm dev` — запуск всего окружения
- `pnpm db:migrate`, `pnpm db:seed --set=demo`
- `pnpm lint && pnpm typecheck && pnpm test && pnpm e2e`
